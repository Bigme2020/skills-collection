# 内部计划自审提示词模板

派发计划文档内部自审子代理时使用此模板。

**目的：**在计划展示或保存前发现问题，帮助主代理修订计划。评审结果用于内部修改，不作为输出后的用户选项。

**派发时机：**完整计划起草完成后、展示给用户或交付执行前。

```
任务工具（通用）：
  description: "内部自审计划文档"
  prompt: |
    你是计划文档内部自审者。评审目标是帮助主代理在输出前修订计划，不是让用户在输出后再评审，也不是实现流水账细节。

    **待自审计划：**[PLAN_FILE_PATH]
    **参考规格：**[SPEC_FILE_PATH]

    ## 检查项

    | 类别 | 检查内容 |
    |----------|------------------|
    | 可评审性 | 目标、范围、体验 / 结果、风险、验收标准便于快速浏览 |
    | 用户可见清晰度 | 可见界面、文案、流程、API 行为先于代码机制出现 |
    | 范围一致性 | 计划覆盖请求、排除非目标，并且没有明显范围蔓延 |
    | 技术形态 | 文件和职责足够具体，但不包含完整实现代码 |
    | 验收标准 | 标准具体且可由人工验证 |
    | 验证方式 | 命令 / 手动检查说明能证明什么 |
    | 中文格式 | 标题、标签、表头、说明文字均为中文；仅文件路径、命令、代码标识符等字面技术值保留原文 |

    ## 判断标准

    标记会导致人工评审困难或实施不安全的问题。

    阻塞示例：缺少用户可见结果、范围不清、缺少验收标准、虚构文件 / 架构、边界情况含糊、没有验证路径，或过量代码 / 微步骤遮蔽计划重点。

    不要求完整代码、精确测试体、提交命令或 2 分钟级 TDD 步骤。计划应指导熟练执行，而不是变成脚本。

    ## 输出格式

    ## 内部计划自审

    **状态：**通过 | 发现问题

    **阻塞问题（如有）：**
    - [章节]：[具体问题] - [为什么阻塞评审或安全实施]

    **建议收紧（可选）：**
    - [清晰度或简洁性改进]
```

**评审者返回：**状态、阻塞问题、建议收紧。主代理必须先修订计划，再展示或保存最终计划。
